## 3. Findings (most severe first)

### E2E-01 — BLOCKER — Account recovery request can never be submitted from the app
- **Feature/screen:** FR-ACC-10 recovery, 1.8rec2 → 1.8rec3 (`AccountRecoveryConfirmScreen`).
- **Steps:** Login → "Forgot password?" on an account without a verified email (e.g. Nimali `+94770000005`) → "Neither of these works for me" → "Recover my account" → enter NIC `200112345678`, birthdate `2001-06-15`, legal name `Nimali Fernando` → "Submit request".
- **Expected:** 1.8rec3 "Request received. An admin will review it…"; a request row is created; status screen survives an app restart.
- **Actual:** a form-level error "This device can't start an account recovery request." and nothing is sent (`AccountRecoveryRequest` stays empty; backend never receives the call).
- **Cause (read from code):** `recoveryDevice.js` `randomId()` throws that exact sentence when `globalThis.crypto.getRandomValues` is missing, which is the case in this RN/Hermes runtime. So every device fails, and the flow cannot be completed from any user's device.
- **Evidence:** `M1-1.8rec3-submitted.png`, `M1-1.8rec2-filled.png`; DB `select * from "AccountRecoveryRequest"` → 0 rows. Backend half works (see C7).
- **Files:** `mobile/src/screens/account/recoveryDevice.js:19-26` (needs a CSPRNG source that exists in RN, e.g. `expo-crypto`/a polyfill — a dependency change for the owner to decide), `AccountRecoveryConfirmScreen.js:83-84`.

- Registration signs the person in and enters the app (home shell); employer step 5 back/close leave for the app. (Not exercised: blocked.)
- Masked email on the forgot-password screen (shows `k***********@example.com`: first letter + one `*` per remaining local-part character).
- No success banner after password / display-name / NIC changes; the screen simply returns to Settings.
- Undrawn error copy: "Passwords do not match." (change password and web reset page), "A NIC is 12 digits, or 9 digits followed by V or X.", "That code doesn't match…" reused for the reset-code screen, the offline sentence, "Too many attempts. Wait a few minutes…".
- The Home screen for a signed-out user is engineering scaffolding (M0/1.1 not built); the tab shells are placeholders ("Employer shell", …) and the bio/endorsement rows and Notification preferences are other modules' screens.
- Password-reset and email-change links open minimal server-rendered pages (not deep links).
- Change-password rate limit trips on the 6th attempt (5 allowed); reset-code limit trips on the 6th wrong code.
- App is light-only (no dark theme) — nothing in M1 specifies one.
